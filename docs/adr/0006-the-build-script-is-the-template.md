# The repository's build script is the console's release template

The console offers a multi-platform release workflow (Windows / macOS-Intel / macOS-Arm / Linux, builds uploaded to the GitHub Release), and the natural place to keep such a workflow is `.github/workflows/release-target.yml` in this repository — a file GitHub actually runs. The console therefore compiles that same file in with `include_str!` and writes it out verbatim when a repository adopts the template, naming the adopting repository in a header line. One file means the demo's own build and the template
cannot drift apart, and a template bug is a bug in the thing being demoed rather than in a copy of it. Considered keeping a separate `templates/` copy (rejected: two files that drift) and generating the YAML from the console's form model (rejected: a four-platform matrix with `needs`, a matrix strategy and a release job is past what the form expresses, and the generated text would no longer be the file that ran).
