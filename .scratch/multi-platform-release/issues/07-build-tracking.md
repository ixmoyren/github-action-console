# 07: 构建追踪：把三个事实分开

**What to build:** 一次构建的完整视图：状态与 job/step、原始日志、构建产物（artifact，会过期）、该版本的发布资产（Release asset），以及本次的源码 ref 与打包配置名。三件事各自标注时间与出处，不能互相替代。

**Blocked by:** 04（CI 模板）

**Status:** ready-for-agent

- [ ] 显示 run 的 status / conclusion、job 与 step 状态、日志
- [ ] 列出构建产物（含大小、是否过期）与发布资产（含下载地址）
- [ ] 显示本次的源码 ref / commit、打包配置名与 target
- [ ] 三个事实在界面上分开标注：构建完成 / 产物可获取 / 已登记发布（含各自时间）
- [ ] 构建产物过期后，"产物可获取"不再成立，但历史构建记录仍在
- [ ] 单元测试：状态与三个事实的推导（含过期、缺资产、失败构建）

## Comments

已实现：运行详情里新增"发布事实"一节（`labels::RELEASE_FACTS_*`），把三个事实并排写清楚——版本 / 发布目标 / 打包配置来自这次 dispatch，`构建完成`取 run 状态，`产物可获取`同时报构建产物（含过期数量）与 release asset（含下载地址），`已登记发布`列出指向该版本的通道指针。三者各自独立：绿色构建只是"构建完成"，产物过期只影响"产物可获取"，"已登记发布"只认指针。不是控制台触发的运行显示"无法确定版本与目标"而不是编一个。`facts_for_run` 与状态推导都有测试（`tests/release_flow.rs`、`src/release.rs`）。
