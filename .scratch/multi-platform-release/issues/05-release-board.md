# 05: 发布看板：目标 × 通道

**What to build:** 看板视图：行为发布目标，列为通道（LTS / latest / dogfood），格里显示当前指针（发布版本或空）以及该目标在该版本上的发布状态；每格能跳到最近一次相关构建的运行详情。状态推导要区分"构建完成""产物可获取""已登记发布"三件事（参照 `CONTEXT.md` 的发布状态取值）。

**Blocked by:** 01（清单）、02（指针）

**Status:** ready-for-agent

- [ ] 行 = 清单里的发布目标，列 = 通道，格子 = 指针 + 该目标该版本的发布状态
- [ ] 指针为空时显示空态，不当作错误
- [ ] 状态区分：待构建 / 构建中 / 构建成功 / 待签名公证 / 待发布 / 已发布 / 失败 / 已取消
- [ ] 模拟目标（清单 `simulated`）不出现"已发布"，最多到"待签名公证 / 待发布"
- [ ] 每格可跳到相关 run 详情
- [ ] 纯函数测试：状态推导的各种输入组合（含模拟目标、缺产物、指针未设置）

## Comments

已实现：`release_state` 纯函数（只有指针才是"已发布"，有模拟步骤的目标停在"待签名公证"）+ `ReleaseBoard::snapshot` + 抽屉里的 目标×通道 表格 + 无头 UI 测试。 **未做**：格子跳到 run 详情（格子已带 run_id，只差点击入口）。

**2026-09-28 右上角两个入口的箭头统一朝右**：工作区标题栏最右边是两个抽屉入口（运行记录、发布看板）。看板的入口本来就是 `发布看板 →`，但同一组里有两处不是朝右：运行记录的入口写的是 `← 运行记录`（a29b6ac 改成抽屉时换的），看板的关闭按钮 `关闭看板` 干脆没有箭头。现在两边一致：

- 抽屉关着：`运行记录 →`、`发布看板 →`
- 抽屉开着：`关闭运行记录 →`、`关闭看板 →`

两个抽屉都从行的右端滑进来、向右滑出去（`DrawerPhase` 的动画方向），箭头统一朝右才跟行为对得上。

**2026-09-28 发布改成"建 tag"**：LTS / latest / dogfood 不再是控制台本地记的通道指针，而是
仓库里的 git tag（新 ADR-0007 取代 0005）。看板上的动作从"发布（登记指针）"变成"创建 Tag"：

- 第二行选分支、读它的提交（`board-branch` / `board-load-commits` / `board-commit`）；没挑提交
  就用这条分支的最新提交。
- 表头每个通道 tag 一颗「创建 Tag」：把 `lts` / `latest` / `dogfood` 指到那个提交上；已经存在
  就移动它（`create_tag` 在 422 时改走 `update_ref --force`）。
- 推上去之后工作流会跑（模板的 `on.push.tags` 加了这三个 tag）。看板按 tag 找这次运行
  （tag push 的 `head_branch` 就是 tag 名），取它的 job，按 job 名 `目标名 · 平台/架构 · 产物`
  认领每一行——成功就是"已发布到这条通道"，带模拟步骤的目标停在"待签名公证"。格子里的
  「查看运行」跳到那次运行的详情（含日志）。

这一步只做了 tag 这条路。 **还没做**：把本地指针那套（`ChannelPointer`、store 里的表、看板上的
旧 `cell()`/`ReleaseCell`、运行详情里"已登记发布"那一行）删干净——现在它们还在，界面上已经
不再使用，留着是过渡状态。

**2026-09-28 看板顶上一排砍到只剩两个下拉**：版本、发布目标、触发构建、编辑清单、读取提交
全去掉了——看板现在只做一件事：把通道 tag 指到一个提交上。

- 分支不再是手输，改成真查询：`list_branches`（一页 100 条）→ 下拉；进仓库读一次，换仓库重来。
- 提交跟着分支自动读：换一条分支就去读它最近的 30 个提交填进下拉，不用再点「读取提交」。
- 建 tag 用的就是这两个下拉：没挑提交就取该分支的最新提交。

连带删掉的 UI 有：触发分区（`board-version`/`board-target`/`board-trigger`）、清单编辑器那一面
（`manifest_editor_ui` + `toggle_manifest_editor` + `submit_manifest`，连它的 UI 测试）、以及
只服务这些的文案与动作键（`TriggerBuild`/`SubmitManifest`/`ManifestEditor`）。应用层里
`trigger` / `save_manifest` / 分发记录那套还在（它们自己的测试还跑着）， **下一步**连同本地指针
一起清掉。

**2026-09-28 建 tag 的动作挪进表单**：表头每列那颗「创建 Tag」撤掉，改成表单第三行——
「版本」下拉（就是通道名，默认 lts，选项 lts / latest / dogfood）+ 一颗「创建」。于是看板顶上
三行：分支、提交、版本 + 创建；表头只剩行名和各 tag 名字，格子还是各自的 job 状态。
