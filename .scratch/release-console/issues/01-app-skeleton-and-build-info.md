# 01: 应用骨架与自身构建信息

**What to build:** 启动应用即出现窗口，并在固定位置始终显示应用自身的版本号、构建目标（target triple）与打包配置标识（未注入时显示为未指定），让用户随时知道自己在用哪个构建。此时应用还不能连接 GitHub——这条票只是打通"构建期信息 → 应用层 → UI"这条最窄的完整路径，并把代码切成可测的形状，为后续所有票建立测试缝。

**Blocked by:** None（可立即开始）

**Status:** ready-for-agent

- [ ] `cargo run` 打开一个窗口，固定位置显示版本号、target triple、打包配置标识
- [ ] 包已拆为 library 与极薄 binary（binary 只做组合根，不含业务逻辑）
- [ ] `cargo test` 在无网络、无 GitHub 凭据的环境下通过
- [ ] 界面文案集中在一个字符串模块，中文单语；主题跟随系统明暗
- [ ] 版本号、构建目标、打包配置标识的取值由纯函数产出，并有单元测试覆盖"缺失打包配置标识"的情形
