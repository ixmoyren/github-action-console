## Comments

**2026-09-27 从运行列表直接拿构建产物**：跑完的那一行，「已完成」是一颗按钮。点它就去问
GitHub 这次运行产出的构建产物； **真有可下载的产物**才在这一行 **下面、表格里面**展开详情，
详情里只有构建产物（名字、大小、过期标记 + 下载入口；大到要确认的，确认/取消就摆在那一
条上）。没有产物就只在状态栏说一声 `这次运行没有可下载的构建产物。`，不展开空盒子。

为此运行列表不再是 `DataTable`：它的行高由内部的 `uniform_list` 统一给定，行不会长高，
塞不进"在行下面展开"的详情。现在表头、列宽、排序（点表头，升/降/原序三态）和展开都由
`runs.rs` 自己做，样式照旧；代价是列宽不能拖拽调整了。表头留在原地，行多了滚下面那截。

顺带一个必须动的改动：详情里的下载走 `download_artifact`，它原先从"打开着的运行详情"取
仓库名；运行列表这条路根本不用先打开详情，所以改成取当前工作区的仓库。

覆盖测试：`the_completed_run_expands_its_artifacts_in_the_table`（跑完的行状态是按钮、还在跑
的不是；详情夹在这一行与下一行之间；下载入口在里面；点表头能排序；点一下就回去取数；收起来
就没了），展开规则本身由 `runs::run_build_opens`（拿到了 且 产物非空）守着。
